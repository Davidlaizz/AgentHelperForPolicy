## 4. 三条稳定演示问题

以下演示问题使用 `LLM_PROVIDER=mock` 跑通，用于证明 Agent 编排、RAG 检索、资格判断、流程生成和后台轨迹能力。

### 4.1 演示一：奖学金政策问答与条件追问

用户问题：

```text
我挂过一门课，还能申请奖学金吗？
```

运行结果摘要：

| 项目 | 结果 |
|---|---|
| intent | `eligibility_check` |
| case_type | `scholarship` |
| risk_level | `medium` |
| missing_slots | 4 |
| citations | 5 |
| 命中文档 | 西安电子科技大学本科生学校奖学金管理评定办法（修订） |

Agent 运行路径：

```text
memory_read -> intent -> case -> slot -> retrieval -> evidence -> followup -> risk -> answer -> memory_write
```

讲解要点：

1. 系统不是直接下结论，而是识别到用户在做奖学金资格判断。
2. 因为还缺少排名、成绩、处分等条件，系统进入 `FollowupAgent`。
3. 风险等级为 `medium`，说明信息不足时不会给绝对结论。
4. 后台可展示完整运行路径和节点耗时。

### 4.2 演示二：转专业资格判断与流程生成

用户问题：

```text
我是大一，绩点3.6，无挂科，无处分，想转入计算机专业，今年可以申请转专业吗？
```

运行结果摘要：

| 项目 | 结果 |
|---|---|
| intent | `eligibility_check` |
| case_type | `major_transfer` |
| risk_level | `low` |
| missing_slots | 0 |
| citations | 5 |
| 命中文档 | 关于2024级大类专业分流有关工作安排的通知；大类分流操作指南（学生） |

Agent 运行路径：

```text
memory_read -> intent -> case -> slot -> retrieval -> evidence -> eligibility -> workflow -> risk -> answer -> memory_write
```

讲解要点：

1. 用户提供了年级、绩点、挂科、处分、目标专业等关键信息。
2. `SlotAgent` 抽取条件后，系统判断缺失条件为 0。
3. 路由进入 `EligibilityAgent` 做资格初判。
4. 随后进入 `WorkflowAgent` 生成材料和流程线索。
5. 该案例最适合展示“从问答到办事路径”的升级。

## 5. 路演讲解脚本

### 5.1 一句话定位

智策通不是一个普通政策问答机器人，而是一个面向政策服务场景的可观测多 Agent 政策理解与精准服务平台。

### 5.2 技术路线讲法

系统底层使用 LlamaIndex 构建政策 RAG 知识库，负责政策文件解析、切片、向量检索和出处召回。

在问答链路上，系统引入 LangGraph，将政策服务拆解成多个专业 Agent，包括记忆读取、意图识别、事项建模、条件抽取、政策检索、证据整理、资格判断、流程生成、风险校验、答案生成和记忆写入。

每个 Agent 都围绕统一状态对象运行，系统会记录每次运行的 `run_id`、节点顺序、输入摘要、输出摘要、耗时和状态，并在管理后台展示。

### 5.3 产品价值讲法

用户不需要理解复杂政策文件，只需要自然语言提问。系统不仅能回答“政策是什么”，还能进一步判断“我是否符合条件”，并整理“我下一步要准备哪些材料、走什么流程”。

对管理者来说，后台可以看到高频问题、政策文件状态、标准答案，以及每一次 Agent 运行轨迹。这让 AI 政策服务具备可追踪、可解释和可治理能力。

### 5.4 比赛创新点讲法

1. 从普通 RAG 问答升级为可控式多 Agent 状态图。
2. 从给答案升级为给判断、材料和流程。
3. 从黑盒 AI 升级为可观测、可审计、可治理的政策服务过程。
4. 从高校政策场景出发，但架构可扩展到城市青年政策、企业政策和政府服务。

## 6. 后台演示顺序

建议演示顺序：

1. 打开前端首页，说明智策通的政策服务定位。
2. 进入问答页，输入奖学金问题，展示系统追问和政策依据。
3. 输入转专业问题，展示资格判断和流程生成。
4. 输入毕业流程问题，展示风险提示和出处引用。
5. 进入管理后台 `/admin`。
6. 展示政策文件、知识库数量、热门问题。
7. 展示“Agent 架构与运行轨迹”模块。
8. 选中最近运行记录，展示每个 Agent 节点的执行步骤和耗时。
