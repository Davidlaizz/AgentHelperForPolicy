# V1.0 高校政策场景适配规划

## 1. 检查结论

当前系统已经具备通用政策问答、RAG 引用、Agent 追问、材料/流程线索和后台治理能力，但 8 类高校政策服务的覆盖程度不均衡。

| 场景 | 知识库资料 | 事项中心 | Agent 识别/追问 | 资格判断 | 当前状态 |
|---|---|---|---|---|---|
| 奖学金 | 已有奖学金评定办法 | 已有 | 已有 | 基础可用 | 基本满足 |
| 助学金 | 暂无正式政策 | 仅首页卡片 | 暂无 | 暂无 | 不满足 |
| 转专业 | 已有大类分流通知和指南 | 已有 | 已有 | 基础可用 | 基本满足 |
| 保研 | 暂无正式政策 | 仅首页卡片 | 暂无 | 暂无 | 不满足 |
| 毕业 | 已有毕业设计论文条例 | 已有 | 已有 | 部分可用 | 部分满足 |
| 请假 | 暂无正式政策 | 仅首页卡片 | 暂无 | 暂无 | 不满足 |
| 处分 | 暂无正式政策 | 仅首页卡片 | 仅作为其他事项风险条件 | 暂无独立事项 | 不满足 |
| 学籍管理 | 已有学籍信息变更表 | 已有 | 已有识别但无 slots | 弱支持 | 部分满足 |

当前可稳定演示的主链路仍然是：

1. 奖学金政策问答
2. 转专业/大类分流资格判断
3. 毕业设计/论文政策问答
4. 学籍信息变更材料查询

## 2. 当前能力边界

### 2.1 已满足能力

- 前端首页已经展示 8 类高校政策服务入口
- `/cases` 已覆盖奖学金、转专业、毕业设计/论文、学籍信息变更
- `/chat` 可对已有知识库资料进行政策问答并展示引用
- `/eligibility` 可演示转专业和奖学金类条件追问
- 后台可上传、解析、索引 PDF/DOCX/DOC/HTML
- M0 正式资料已入库，政策库可展示 5 份文件

### 2.2 主要不足

- 首页列出的 8 类服务中，助学金、保研、请假、处分还没有正式知识库资料
- 事项中心只做了 4 类卡片，和首页 8 类入口不一致
- Agent 当前只显式建模了 `major_transfer`、`scholarship`、`thesis`，学籍管理缺少 slots，助学金/保研/请假/处分缺少 case type
- 毕业类目前主要是毕业设计/论文，不等于完整毕业资格、学位授予、结业补做等全流程
- 奖学金规则尚未细分校长奖、综合发展奖学金、单项奖学金、毕业生奖学金等子场景

## 3. 场景适配优先级

### P0：先补齐前端服务一致性

目标：让用户看到的 8 类服务都能进入事项中心，并明确哪些是“已接入政策库”、哪些是“待补政策”。

任务：

- `/cases` 扩展为 8 类卡片
- 每类卡片提供常见问题、材料线索、办理步骤、风险提醒
- 对无资料场景显示“待上传政策文件，当前仅可通用咨询”
- 首页快捷事项跳转到对应事项筛选

验收：

- 首页 8 类服务与事项中心 8 类服务一致
- 不会出现入口有、详情页没有的断层

### P1：补齐知识库资料

目标：让 8 类服务至少各有 1 份正式政策文件或表单资料。

建议补充：

- 助学金：家庭经济困难学生认定办法、国家助学金评审办法、申请表
- 保研：推荐免试研究生工作实施办法、综合排名/加分细则、公示通知
- 请假：学生请销假管理办法、病假/事假审批流程、证明材料要求
- 处分：学生违纪处分规定、考试违纪处理办法、处分解除/影响说明
- 毕业：毕业资格审核、学位授予、结业/补做、离校流程
- 学籍管理：休学、复学、退学、转学、保留学籍等完整办法

验收：

- 每类服务至少 1 份 active 且 indexed 的政策文件
- 每类服务至少 5 个可检索测试问题
- 政策库按类别筛选时不为空

### P2：扩展 Agent 事项模型

目标：让 8 类服务都具备可追问、可记忆、可生成风险提示的事项模型。

建议新增 case type：

- `grant`：助学金
- `postgraduate_recommendation`：保研/推免
- `leave_request`：请假
- `discipline`：处分
- `student_status`：完整学籍管理，替换或扩展现有 `status_change`
- `graduation`：完整毕业要求，和 `thesis` 区分

建议 slots：

| 场景 | 关键 slots |
|---|---|
| 助学金 | 年级、困难认定等级、家庭经济情况、是否已建档、申请年度、材料状态 |
| 保研 | 年级、专业排名、绩点、英语成绩、科研竞赛、处分记录、挂科记录 |
| 请假 | 请假类型、请假天数、起止时间、是否离校、证明材料、审批层级 |
| 处分 | 违纪类型、发生时间、处理阶段、是否申诉、是否影响评奖/保研/毕业 |
| 学籍管理 | 办理类型、变更字段、证明材料、学院审核状态、教务审核状态 |
| 毕业 | 毕设状态、学分完成、处分记录、论文/答辩状态、是否结业补做 |

验收：

- 每类事项能识别意图
- 关键条件缺失时能追问
- 条件补齐后能生成 `pending / likely_eligible / not_eligible`

### P3：优化问答与流程输出模板

目标：每类服务的回答都符合“政策依据 + AI 推断 + 材料 + 流程 + 风险”的稳定格式。

任务：

- 增加按场景的回答模板
- 对无资料场景强制提示“缺少正式政策依据”
- 对时效性强的通知类政策提示年度风险
- 对处分、保研、毕业等高影响事项提高风险等级

验收：

- 回答中不裸露 Markdown 标记
- 无依据时不编造政策
- 高风险事项有人工复核提示

## 4. 推荐实施顺序

### 第 1 批：服务入口补齐

- 扩展 `/cases` 到 8 类
- 增加类别筛选和“政策覆盖状态”
- 优化首页跳转到事项中心的对应类别

### 第 2 批：知识库资料补齐

- 按 8 类目录整理 `M0_交付物`
- 上传/入库/索引缺失政策
- 增加 `docs/v1-scenario-test-set.md`

### 第 3 批：Agent 模型补齐

- 扩展 `backend/app/services/agent/rules.py`
- 扩展资格判断规则和风险规则
- 增加 M6 场景冒烟测试

### 第 4 批：验收与演示脚本

- 为每类服务准备 2 个稳定问题
- 选出 3 条主讲链路和 5 条辅助展示链路
- 管理后台看板增加按政策类别统计覆盖情况

## 5. V1.0 通过标准

V1.0 若要宣称覆盖“高校政策奖学金、助学金、转专业、保研、毕业、请假、处分、学籍管理”，建议至少满足：

- 8 类服务均有事项入口
- 8 类服务均有至少 1 份正式政策或表单资料
- 8 类服务均可问答并返回出处
- 6 类以上具备材料/流程线索
- 4 类以上具备资格判断或条件追问
- 高风险类事项有人工复核和不确定性提示

当前系统距离该标准的主要差距在“资料覆盖”和“Agent 事项模型覆盖”。
