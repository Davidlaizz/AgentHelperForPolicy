# 数字乡村静态展示前端规划

## 1. 文档目的

本文档用于指导数字乡村场景的第一版可展示前端实现。

当前目标不是先完成后端联调，而是先在 `http://127.0.0.1:3001` 做出一个完整、可讲解、可点击、可演示的静态前端界面，用于展示“数字乡村智能体平台”的产品形态和业务闭环。

静态展示版需要服务三个目的：

1. 对外演示：让观众快速理解平台能做什么。
2. 产品定型：先固定页面结构、模块关系、演示话术和视觉风格。
3. 后续开发承接：后端 API、RAG、Agent 和数据库隔离完成后，可以平滑替换静态数据。

## 2. 总体原则

### 2.1 前端独立

数字乡村前端新增独立工程：

```text
frontend-digital-village
```

运行地址：

```text
http://127.0.0.1:3001
```

高校场景前端继续保留：

```text
frontend
http://127.0.0.1:3000
```

数字乡村静态展示版不直接改造高校前端，避免影响高校政策服务演示。

### 2.2 静态优先

第一版先不依赖后端接口，所有内容使用前端本地 mock 数据。

静态版应包含：

- 可点击导航
- 可切换模块
- 可填入或选择演示问题
- 可展示模拟回答
- 可展示模拟政策依据
- 可展示模拟看板数据
- 可展示模拟办事流程

即使没有后端，也要让演示者可以从首页进入三大模块并完成一条讲解闭环。

### 2.3 展示优先级

优先保证页面完整度和演示叙事，不追求第一版功能真实计算。

优先级从高到低：

1. 首页工作台能一眼看出平台定位。
2. 政策问答、智慧农业、办事引导三大模块都有独立页面和演示路径。
3. 每个模块都有示例输入、模拟输出、依据或步骤。
4. 后台看板能展示平台运营价值。
5. 样式统一、响应式可用、按钮点击有反馈。

## 3. 产品定位与信息架构

平台名称建议：

```text
数字乡村智能体平台
```

一句话定位：

```text
面向农业农村和城乡社区的政策问答、智慧农业诊断与办事引导工作台。
```

核心用户：

- 农户
- 村干部
- 合作社负责人
- 返乡创业者
- 基层服务人员
- 学生实践团队

核心模块：

| 模块 | 作用 | 演示重点 |
|---|---|---|
| 政策问答 | 把涉农政策解释成能理解、能执行的答案 | 政策依据、适用条件、材料提醒 |
| 智慧农业 | 把生产、销售、经营问题转化为数字化方案 | 问题诊断、落地步骤、政策联动 |
| 办事引导 | 把“我要办事”变成流程和材料清单 | 办理步骤、缺口检查、风险提示 |

辅助模块：

- 事项中心
- 政策库
- 管理后台

## 4. 页面规划

### 4.1 首页 `/`

首页是第一屏演示入口，不做营销长页，直接呈现可用工作台。

核心内容：

- 顶部导航：工作台、政策问答、智慧农业、办事引导、事项中心、政策库、管理后台。
- 首屏标题：数字乡村智能体平台。
- 副标题：政策问答、智慧农业、办事引导三位一体。
- 三个主入口卡片：
  - 政策问答
  - 智慧农业
  - 办事引导
- 演示问题区：
  - 买农机能不能申请补贴？
  - 我们村苹果卖不出去，能做什么数字化项目？
  - 办合作社需要哪些材料？
- 平台闭环展示：
  - 政策资料
  - 智能检索
  - 多 Agent 诊断
  - 方案生成
  - 运营沉淀
- 数据摘要：
  - 政策资料数
  - 服务事项数
  - 高频问题数
  - 演示场景数

首页视觉要求：

- 不做大面积空洞 hero。
- 首屏必须看到主功能入口。
- 使用农业绿色、科技蓝、暖黄色作为辅助色，但避免整页单一绿色。
- 卡片半径保持克制，建议不超过 8px。
- 使用 `lucide-react` 图标表达模块，不使用 emoji。

### 4.2 政策问答 `/chat`

目标：静态模拟“问一句政策，得到可信答案”的体验。

页面结构：

- 左侧或顶部：示例问题列表。
- 中间：问答输入框和发送按钮。
- 右侧或下方：模拟回答区域。
- 回答下方：政策依据、AI 推断、风险提醒。

示例问题：

```text
买农机能不能申请补贴？
返乡创业有没有贷款优惠？
合作社能申请哪些农业项目？
我想做农产品直播，有没有政策支持？
```

模拟输出结构：

```text
简要结论
适用政策
你可能符合的条件
需要准备的材料
办理部门或咨询渠道
风险提醒
政策依据
```

交互要求：

- 点击示例问题后，输入框填入问题并展示对应模拟回答。
- 手动输入任意内容后，点击发送展示通用模拟回答。
- 回答区域支持简单 Markdown 样式，不裸露 `**`。
- 按钮点击后有短暂 loading 或状态变化，增强可展示性。

### 4.3 智慧农业 `/agriculture`

目标：静态模拟“农业问题诊断 + 数字化方案 + 政策联动”。

页面结构：

- 问题场景选择：
  - 农产品卖不出去
  - 想建设智慧农业示范点
  - 农民不会直播
  - 村集体经济收入低
- 诊断结果面板：
  - 问题类型
  - 核心痛点
  - 涉及对象
  - 数字化方向
  - 可匹配政策
  - 落地步骤
  - 建议采集数据
  - 风险和前置条件
- 方案卡片：
  - 直播助农培训方案
  - 农产品品牌建设方案
  - 智慧农业示范点方案
  - 村集体数字化运营方案

展示重点：

- 让观众看到平台不只是“查政策”，还可以把乡村问题转成行动方案。
- 输出要像基层工作建议，不像抽象报告。
- 每个方案都要关联到政策问答或办事引导入口。

### 4.4 办事引导 `/guide`

目标：静态模拟“我要办一件事”的流程引导。

页面结构：

- 事项选择：
  - 农机购置补贴
  - 返乡创业贷款
  - 合作社办理
  - 农产品电商入驻
  - 村级项目申报
  - 医保养老代办
- 条件卡片：
  - 所在地区
  - 主体身份
  - 当前阶段
  - 已有材料
- 结果面板：
  - 适用对象
  - 前置条件
  - 必备材料
  - 办理步骤
  - 咨询或办理部门
  - 当前缺口
  - 注意事项

交互要求：

- 点击不同事项后切换静态流程。
- 材料清单用 checkbox 展示，可勾选模拟“已准备”。
- 根据勾选状态展示“当前还缺什么”。
- 高风险事项用醒目的提示条展示人工复核建议。

### 4.5 事项中心 `/cases`

目标：按数字乡村常见事项组织入口。

事项分类：

- 农业补贴
- 农机购置
- 农产品电商
- 返乡创业
- 合作社办理
- 村集体经济
- 智慧农业建设
- 社区治理
- 农村公共服务

每个事项卡片包含：

- 事项名称
- 适用对象
- 常见问题
- 需要材料
- 推荐进入模块：政策问答、智慧农业或办事引导

### 4.6 政策库 `/policies`

目标：展示未来 RAG 知识库形态。

静态展示内容：

- 政策文件列表
- 政策分类筛选
- 地区层级筛选
- 适用主体筛选
- 政策摘要
- 引用片段预览

第一批模拟政策类型：

- 数字乡村建设
- 乡村振兴
- 农业补贴
- 农机农技
- 农产品电商
- 返乡创业
- 农村金融
- 社区治理

### 4.7 管理后台 `/admin`

目标：展示平台可运营、可观测、可沉淀。

后台静态模块：

- 总览看板
- 高频问题
- 政策知识库
- 事项服务
- 智慧农业诊断记录
- Agent 运行轨迹
- 系统配置

核心指标：

- 今日咨询数
- 高频政策问题
- 热门事项
- 主体类型分布
- 地区咨询分布
- 材料缺口排行
- 项目线索数量

注意：

- 后台第一版只做静态数据和 tab 切换。
- 不做真实上传、删除、编辑。
- 可保留“演示模式”标识，避免误解为真实后台。

## 5. 视觉与交互规范

### 5.1 视觉风格

推荐风格：

```text
基层政务 + 数字农业 + 可信工作台
```

关键词：

- 清晰
- 稳重
- 可执行
- 可信
- 有温度

避免：

- 过度营销风首页
- 大面积纯绿色
- 复杂渐变和装饰性光斑
- 只有卡片堆叠，没有业务流程
- 用大量说明文字解释功能

### 5.2 色彩建议

建议使用多色但克制的工作台色彩：

| 用途 | 建议色彩方向 |
|---|---|
| 主色 | 农业绿色 |
| 科技辅助 | 蓝色 |
| 产业/收益 | 暖黄色 |
| 风险提醒 | 红色或琥珀色 |
| 页面背景 | 低饱和灰白 |
| 文本 | 深灰或近黑 |

要求：

- 不把整站做成单一绿色。
- 正文对比度满足 4.5:1。
- 功能状态不能只依赖颜色，需要配合文字或图标。

### 5.3 组件规范

优先使用：

- 图标按钮：用于导航、展开、刷新、搜索等动作。
- 分段控件：用于三大模块或事项状态切换。
- Checkbox：用于材料是否已准备。
- Tabs：用于后台分区。
- 表格：用于政策库和高频问题。
- 进度步骤条：用于办事流程。

避免：

- 把所有内容都做成大卡片。
- 卡片套卡片。
- 无意义的装饰性图形。
- 文字按钮过多导致操作层级混乱。

### 5.4 响应式要求

第一版至少适配：

- 桌面：`1440px`
- 笔记本：`1280px`
- 平板：`768px`
- 手机：`390px`

移动端要求：

- 导航收敛为顶部菜单或底部主入口。
- 三大模块入口优先展示。
- 表格改为列表卡片。
- 不出现横向滚动。
- 按钮和可点击区域不小于 44px。

## 8. 演示脚本

建议第一条完整演示路径：

1. 打开首页，说明平台面向农业农村和城乡社区。
2. 点击“政策问答”，选择“买农机能不能申请补贴？”。
3. 展示简要结论、适用政策、材料提醒和政策依据。
4. 切换到“智慧农业”，选择“我们村苹果卖不出去”。
5. 展示问题诊断、直播电商/品牌建设方案和政策联动。
6. 切换到“办事引导”，选择“办合作社需要哪些材料？”。
7. 勾选已有材料，展示缺口清单和办理步骤。
8. 进入后台，展示高频问题、材料缺口和项目线索沉淀。

这条路径要控制在 3 到 5 分钟内讲完。

## 11. 与后端联调的衔接

静态展示版完成后，再按 `digital-village-agent-platform-plan.md` 第 10 章接入后端隔离能力。

替换顺序：

1. 政策库 mock 数据替换为 `/api/digital-village/documents`。
2. 政策问答 mock 回答替换为 `/api/digital-village/chat`。
3. 政策依据 mock 数据替换为 `/api/digital-village/rag/search`。
4. 后台 mock 指标替换为 `/api/digital-village/management/dashboard`。
5. 高频问题 mock 数据替换为 `/api/digital-village/management/hot-questions`。

替换要求：

- 保留静态 fallback，后端不可用时仍能演示。
- API 接入通过统一 client 封装，不在页面里散落 fetch。
- 所有数字乡村请求只访问 `/api/digital-village/*`。
