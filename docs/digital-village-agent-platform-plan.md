# 数字乡村智能体平台适配规划

## 1. 文档目的

本文档用于将智策通从高校政策服务场景扩展到数字乡村场景，明确新业务域的总体定位、三大核心模块、智能体中台能力、数据资料要求和阶段实施路线。

数字乡村场景的大基调是：

- 面向农业农村和城乡社区发展中的真实问题
- 帮助农民、村干部、基层工作人员、返乡创业者和学生团队理解政策
- 通过智能体中台提供政策问答、智慧农业支持和办事引导
- 将政策知识、基层问题、产业服务和项目孵化连接成可追踪、可运营的服务闭环

## 2. 总体定位

数字乡村智能体平台不是单一聊天机器人，而是一个围绕基层需求运转的智能服务中台。

核心目标：

1. 让政策更容易被基层用户理解
2. 让农业生产、经营和乡村治理问题能被结构化诊断
3. 让办事流程、材料准备和办理部门更清晰
4. 让后台沉淀高频问题、政策热度、服务记录和项目线索

主要服务对象：

| 用户类型 | 典型诉求 |
|---|---|
| 农户 | 看懂补贴、贷款、农机、种养殖、电商等政策 |
| 村干部 | 查询政策依据，组织村级服务，推进治理和产业项目 |
| 返乡创业者 | 匹配创业、农业、电商、金融、场地和培训资源 |
| 合作社/家庭农场 | 查询主体扶持、项目申报、品牌建设和经营政策 |
| 学生团队 | 将乡村问题转化为创新实践、红旅项目或服务方案 |
| 基层服务人员 | 快速生成办事清单、材料清单和政策解释口径 |

## 3. 三大核心模块

### 3.1 政策问答模块

政策问答模块负责把政策原文转化为基层用户能理解、能执行的说明。

#### 3.1.1 覆盖范围

- 数字乡村建设政策
- 乡村振兴政策
- 农业补贴政策
- 农机购置与农技推广政策
- 农产品电商和直播助农政策
- 返乡创业和创业担保贷款政策
- 农村金融、保险和信贷政策
- 合作社、家庭农场、农业企业扶持政策
- 农村养老、医疗、教育和公共服务政策
- 城乡社区治理、基层治理和村级服务政策

#### 3.1.2 智能化能力

- 政策通俗解释：将政策条款解释成简单、明确、口语化的表达
- 条件初判：根据用户身份、地区、主体类型和项目阶段判断可能适用性
- 材料提示：从政策中抽取申请材料、证明材料和办理条件
- 风险提示：标记地区限制、时间限制、主体限制和政策时效风险
- 出处引用：延续现有 RAG 能力，展示政策依据、文件名和引用片段

#### 3.1.3 典型问题

```text
我想做农产品直播，有没有政策支持？
买农机能不能申请补贴？
返乡创业有没有贷款优惠？
村里想发展集体经济，有哪些政策可以用？
合作社能申请哪些农业项目？
```

#### 3.1.4 推荐输出结构

```text
简要结论
适用政策
你可能符合的条件
需要准备的材料
办理部门或咨询渠道
风险提醒
政策依据
```

### 3.2 智慧农业模块

智慧农业模块负责把农业生产、经营、销售和数字化转型问题转化为可执行建议。

它不只回答政策，还要帮助用户理解“农业问题是什么、可以怎么数字化、能否匹配政策和项目资源”。

#### 3.2.1 覆盖范围

- 种植、养殖、农机、农技推广
- 农产品销售、品牌建设、直播电商
- 农产品仓储、冷链、物流和供应链
- 农业生产数字化、物联网、遥感、农情监测
- 农业经营主体数字化管理
- 农村电商服务站和数字服务站
- 村集体经济数字化运营
- 农业社会化服务

#### 3.2.2 智能化能力

- 问题诊断：识别用户描述中的农业生产、销售、管理或服务问题
- 场景分类：将问题归类为生产效率、销售渠道、品牌建设、经营管理、数字能力等类别
- 方案建议：给出数字化工具、服务流程、运营方式和试点路径
- 政策联动：将农业问题自动关联到可能适用的政策和资源
- 项目孵化：把乡村问题整理成可申报、可路演、可落地的项目方案
- 数据指标建议：提供产量、销量、服务人数、增收效果、培训次数等可量化指标

#### 3.2.3 典型问题

```text
我们村苹果卖不出去，能做什么项目？
村里想做智慧农业示范点，应该从哪里开始？
合作社想做农产品品牌化，有哪些步骤？
农民不会用直播工具，怎么设计培训方案？
村集体经济收入低，能不能用数字化办法提升？
```

#### 3.2.4 推荐输出结构

```text
问题类型
主要痛点
涉及对象
数字化解决方向
可匹配政策或资源
落地步骤
建议采集的数据
风险和前置条件
```

### 3.3 办事引导模块

办事引导模块负责把“我想办一件事”转化为清晰步骤、材料清单和办理路径。

该模块应尽量减少政策术语，让用户知道下一步去哪里、找谁、带什么、注意什么。

#### 3.3.1 覆盖范围

- 农业补贴申请
- 农机购置补贴办理
- 创业担保贷款咨询
- 合作社、家庭农场、农业企业登记办理
- 农村电商主体备案或平台入驻
- 土地流转、承包经营相关咨询
- 村级项目申报和证明材料准备
- 社保、医保、养老、低保等基层公共服务
- 村级数字服务站代办事项

#### 3.3.2 智能化能力

- 办事事项识别：从用户口语描述中识别具体事项
- 条件追问：追问地区、身份、主体类型、项目阶段、材料状态等关键条件
- 材料清单：区分必备材料、建议材料和需要补充确认的材料
- 流程生成：生成办理步骤、办理部门和办理顺序
- 缺口检查：根据用户已提供信息标记缺失条件和缺失材料
- 高风险提醒：对跨地区、强时效、强资格限制事项提示人工复核

#### 3.3.3 典型问题

```text
我想申请农机补贴，要准备什么？
返乡创业贷款怎么申请？
办合作社需要哪些材料？
村里开证明应该怎么写？
老人不会网上缴医保，可以怎么代办？
```

#### 3.3.4 推荐输出结构

```text
办理事项
适用对象
前置条件
必备材料
办理步骤
咨询或办理部门
当前缺口
注意事项
```

## 4. 智能体中台编排

数字乡村适配应复用当前 LangGraph 多 Agent 架构，在现有政策服务链路上增加数字乡村领域识别、问题诊断和办事引导能力。

### 4.1 推荐 Agent 节点

| Agent 节点 | 职责 |
|---|---|
| 场景识别 Agent | 判断问题属于政策问答、智慧农业、办事引导或项目孵化 |
| 主体识别 Agent | 识别农户、村干部、合作社、企业、学生团队、社会组织等主体 |
| 地区识别 Agent | 抽取省、市、县、乡镇、村等地域信息 |
| 政策检索 Agent | 根据政策类别、地区、主体和事项检索政策片段 |
| 问题诊断 Agent | 识别农业农村和城乡社区发展的核心痛点 |
| 政策匹配 Agent | 将用户条件与政策、项目、资源进行匹配 |
| 办事流程 Agent | 生成步骤、材料、办理部门和缺口清单 |
| 项目孵化 Agent | 将乡村问题整理成项目方案、试点计划和价值表达 |
| 风险校验 Agent | 检查时效、地区、资格、材料和政策依据风险 |
| 运营沉淀 Agent | 写入高频问题、项目线索、材料缺口和服务记录 |

### 4.2 推荐调度链路

```text
用户输入
-> 场景识别
-> 主体/地区/事项抽取
-> 政策检索或问题诊断
-> 政策匹配/办事流程/项目孵化
-> 材料与风险校验
-> 输出可执行建议
-> 写入运营数据
```

## 10. 独立前端与后端隔离实施规划

本阶段需要从现有高校政策服务前端中脱胎出数字乡村场景前端，同时确保新场景后端不会影响旧场景后端。

核心原则：

1. 前端独立：高校场景和数字乡村场景分别运行、分别构建、分别维护页面入口。
2. 后端复用但隔离：复用 FastAPI、解析、RAG、Agent、后台能力，但数字乡村使用独立 API 前缀、数据库、向量表、存储目录和运行时配置。
3. 旧场景不受影响：现有高校 `/api/*` 接口、数据库、政策库、热门问题、系统配置和前端 `3000` 端口保持原有行为。

### 10.1 前端工程拆分

推荐新增兄弟应用：

| 场景 | 工程目录 | 本地端口 | 说明 |
|---|---|---|---|
| 高校政策服务 | `frontend` | `3000` | 保持现有页面、路由和 API 调用方式 |
| 数字乡村服务 | `frontend-digital-village` | `3001` | 新增独立前端，复用设计语言和基础组件思路 |

数字乡村前端不直接改造高校前端，而是从高校前端中抽取可复用经验，重新组织为数字乡村业务界面。

建议页面：

- `/`：数字乡村智能服务工作台
- `/chat`：政策问答
- `/agriculture`：智慧农业
- `/guide`：办事引导
- `/cases`：数字乡村事项中心
- `/policies`：政策库
- `/admin`：数字乡村管理后台

前端环境变量建议：

```text
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000/api/digital-village
```

这样数字乡村前端只访问 `/api/digital-village/*`，避免误调用高校场景接口。

### 10.2 后端 API 隔离

后端仍使用同一个 FastAPI 服务进程，但新增数字乡村路由前缀：

```text
/api/digital-village/health
/api/digital-village/chat
/api/digital-village/documents
/api/digital-village/documents/upload
/api/digital-village/documents/{document_id}/parse
/api/digital-village/rag/search
/api/digital-village/management/dashboard
/api/digital-village/management/hot-questions
/api/digital-village/management/policy-chunks
/api/digital-village/management/standard-answers
/api/digital-village/management/agent-graph
/api/digital-village/management/agent-runs
/api/digital-village/management/system-config
```

旧高校接口继续保留：

```text
/api/chat
/api/documents
/api/rag/search
/api/management/*
```

实现要求：

- 数字乡村接口不得复用高校数据库会话依赖。
- 数字乡村接口不得读写高校 `HotQuestion`、`PolicyDocument`、`ChatSession` 等业务数据。
- 数字乡村后台系统配置只修改数字乡村运行时配置，不影响高校问答模型和 RAG 设置。
- CORS 需要同时允许 `http://127.0.0.1:3000` 和 `http://127.0.0.1:3001`。

### 10.3 数据库、向量表与存储隔离

推荐新增独立数据库：

```text
zhicetong_digital_village
```

隔离目标：

| 类型 | 高校场景 | 数字乡村场景 |
|---|---|---|
| PostgreSQL 数据库 | `zhicetong` | `zhicetong_digital_village` |
| API 前缀 | `/api/*` | `/api/digital-village/*` |
| 上传目录 | `backend/storage/uploads` | `backend/storage/digital-village/uploads` |
| 解析目录 | `backend/storage/parsed` | `backend/storage/digital-village/parsed` |
| 向量表 | 现有高校向量表 | `llamaindex_digital_village_policy_chunks` |
| 前端端口 | `3000` | `3001` |

后端需要新增数字乡村数据库 session 和依赖，例如：

```text
DigitalVillageSessionLocal
get_digital_village_db
```

数字乡村路由只允许使用数字乡村 DB session。共享服务层可以通过参数注入不同 session、目录和 RAG 配置，但不能在服务内部写死高校数据库或高校向量表。

### 10.4 配置隔离

数字乡村需要独立配置项，避免后台热更新时影响高校场景。

建议新增配置：

```text
DIGITAL_VILLAGE_DATABASE_URL
DIGITAL_VILLAGE_UPLOAD_DIR
DIGITAL_VILLAGE_PARSED_DIR
DIGITAL_VILLAGE_VECTOR_TABLE
DIGITAL_VILLAGE_LLM_PROVIDER
DIGITAL_VILLAGE_LLM_BASE_URL
DIGITAL_VILLAGE_LLM_MODEL
DIGITAL_VILLAGE_LLM_API_KEY
DIGITAL_VILLAGE_EMBEDDING_PROVIDER
DIGITAL_VILLAGE_EMBEDDING_MODEL
```

默认策略：

- 如果数字乡村 LLM 配置为空，可以先沿用同一个模型服务供应商，但运行时配置对象必须独立。
- 后续数字乡村后台切换模型时，只更新 `DIGITAL_VILLAGE_*` 运行时配置。
- 高校系统配置页和数字乡村系统配置页展示各自的配置状态。

### 10.5 复用边界

可以复用：

- FastAPI 应用进程
- SQLAlchemy 模型定义
- 文档解析器
- RAG 检索服务代码
- LLM provider 封装
- LangGraph Agent 编排框架
- Markdown 渲染组件、页面布局经验、后台交互模式

必须隔离：

- 数据库连接与会话
- 上传文件和解析文件
- 向量索引表
- 热门问题和问答日志
- 标准答案和后台配置
- 前端环境变量和端口
- 数字乡村演示问题、政策类别和事项中心

### 10.6 实施顺序

1. 新建 `frontend-digital-village`，先复刻可运行的页面骨架并绑定 `3001`。
2. 后端新增数字乡村配置、数据库 session、独立 storage 路径和 CORS 端口。
3. 新增 `/api/digital-village/*` 路由层，先打通 health、documents、chat、rag/search。
4. 将 RAG 和 Agent 服务改造为可注入配置，旧高校调用保持默认行为。
5. 接入 3 到 5 份数字乡村政策资料，构建最小政策问答闭环。
6. 补齐智慧农业和办事引导页面，以及数字乡村后台看板。
7. 做双场景回归：`3000` 高校场景可用，`3001` 数字乡村场景可用，两边数据互不串扰。

### 10.7 验收标准

基础验收：

- `http://127.0.0.1:3000` 高校前端保持可访问。
- `http://127.0.0.1:3001` 数字乡村前端可访问。
- `http://127.0.0.1:8000/api/health` 高校后端健康检查保持可用。
- `http://127.0.0.1:8000/api/digital-village/health` 数字乡村后端健康检查可用。

隔离验收：

- 在数字乡村上传政策文件后，高校政策库不出现该文件。
- 在数字乡村问答后，高校热门问题榜不新增该问题。
- 修改数字乡村系统配置后，高校系统配置不变化。
- 数字乡村 RAG 检索只返回数字乡村资料，高校 RAG 检索只返回高校资料。

业务验收：

- 政策问答可以回答农业补贴、乡村振兴、数字乡村建设相关问题。
- 智慧农业可以输出问题类型、痛点、数字化方向和可匹配政策。
- 办事引导可以输出适用对象、材料清单、办理步骤和风险提醒。
