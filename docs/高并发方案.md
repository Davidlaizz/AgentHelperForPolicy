# 智策通高并发方案（10万用户场景）

## 1. 现状瓶颈分析

当前架构在高并发下的主要瓶颈：

| 瓶颈 | 位置 | 影响 |
|------|------|------|
| 同步阻塞 LLM 调用 | `llm_provider.py:41-89` | 每个请求阻塞 90-180s，吞吐量极低 |
| 无连接池配置 | `session.py:7-11` | SQLAlchemy 默认 pool_size=5，远不够 |
| 无缓存层 | 全局 | 相同问题重复调用 RAG + LLM |
| 单进程 Uvicorn | `run.py` | 单核处理，无法利用多核 |
| 向量检索每次重建索引 | `llama_index_adapter.py:113-121` | 每次 `from_vector_store` 开销大 |
| 关键词搜索全表扫描 | `retriever.py:69-129` | ILIKE 查询无索引优化 |
| 同步数据库会话 | `dependencies.py` | 阻塞式 I/O |

## 2. 目标指标

| 指标 | 目标值 |
|------|--------|
| 并发用户数 | 10,000 在线 |
| QPS（问答接口） | 500-1000 |
| P99 延迟 | < 3s（不含 LLM） |
| LLM 调用吞吐 | 100-200 并发请求 |
| 数据库连接数 | < 200 |
| 系统可用性 | 99.9% |

## 3. 架构方案

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                        Nginx / Traefik                          │
│                    负载均衡 + 限流 + 静态资源                      │
└──────────────────────────┬──────────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────────┐
│                    FastAPI 应用层（多实例）                        │
│            Uvicorn workers = CPU核心数 × 2 + 1                   │
│                                                                  │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐        │
│  │ Worker 1 │  │ Worker 2 │  │ Worker 3 │  │ Worker N │        │
│  └────┬─────┘  └────┬─────┘  └────┬─────┘  └────┬─────┘        │
│       │              │              │              │              │
│  ┌────▼──────────────▼──────────────▼──────────────▼─────┐      │
│  │              连接池 + 异步任务队列                        │      │
│  └────┬──────────────┬──────────────┬──────────────┬─────┘      │
└───────┼──────────────┼──────────────┼──────────────┼────────────┘
        │              │              │              │
┌───────▼──────┐ ┌─────▼─────┐ ┌─────▼─────┐ ┌─────▼─────┐
│  PostgreSQL  │ │   Redis   │ │  Celery   │ │  LLM API  │
│  主从 + PgBouncer │ │  缓存+会话 │ │  异步任务  │ │  多实例   │
└──────────────┘ └───────────┘ └───────────┘ └───────────┘
```

### 3.2 分层优化

#### 第一层：接入层（Nginx/Traefik）

- **负载均衡**：多 FastAPI 实例轮询分发
- **限流**：每 IP 10 QPS，每用户 5 QPS
- **静态资源**：前端静态文件直接由 Nginx 提供
- **Gzip/Brotli 压缩**：减少传输体积
- **连接复用**：HTTP/2 + keep-alive

#### 第二层：应用层（FastAPI）

- **多 Worker**：`uvicorn --workers 8`（CPU核心数 × 2 + 1）
- **异步端点**：chat 接口改为 `async def`，使用 `await` 调用 LLM
- **连接池**：SQLAlchemy pool_size=20, max_overflow=10
- **依赖注入**：使用 `asynccontextmanager` 管理会话

#### 第三层：缓存层（Redis）

- **问答缓存**：相同问题 10 分钟内直接返回
- **会话缓存**：用户会话状态缓存
- **热点数据**：热门问题、常用政策片段缓存
- **向量缓存**：embedding 结果缓存

#### 第四层：异步任务层（Celery）

- **LLM 调用**：长耗时任务异步处理
- **文档解析**：PDF/DOCX 解析异步化
- **索引构建**：RAG 索引重建异步化

#### 第五层：数据层（PostgreSQL）

- **主从复制**：一主两从，读写分离
- **连接池**：PgBouncer 管理连接
- **索引优化**：向量索引 + 全文索引
- **分区表**：chat_messages 按时间分区

### 4.2 异步 LLM 调用

**文件**: `backend/app/services/llm_provider.py`

```python
import asyncio
import aiohttp
from functools import lru_cache

class AsyncHttpLLMProvider(LLMProvider):
    def __init__(self):
        self._session = None
    
    async def _get_session(self) -> aiohttp.ClientSession:
        if self._session is None or self._session.closed:
            self._session = aiohttp.ClientSession(
                timeout=aiohttp.ClientTimeout(total=settings.llm_timeout_seconds)
            )
        return self._session
    
    async def generate_async(self, prompt: str, contexts: list[dict]) -> str:
        session = await self._get_session()
        payload = {
            "model": settings.llm_model,
            "messages": [
                {"role": "system", "content": "你是高校政策智能问答助手"},
                {"role": "user", "content": prompt},
            ],
            "temperature": 0.2,
        }
        if settings.llm_max_tokens:
            payload["max_tokens"] = settings.llm_max_tokens
        
        headers = {
            "Content-Type": "application/json",
            "Authorization": f"Bearer {settings.llm_api_key}",
        }
        
        async with session.post(
            normalize_chat_completions_url(settings.llm_api_url),
            json=payload,
            headers=headers,
        ) as response:
            body = await response.json()
            if "choices" in body:
                return body["choices"][0]["message"]["content"]
            raise RuntimeError("LLM 响应格式错误")
    
    def generate(self, prompt: str, contexts: list[dict]) -> str:
        # 同步包装，兼容现有代码
        loop = asyncio.get_event_loop()
        return loop.run_until_complete(self.generate_async(prompt, contexts))
```

### 4.3 Redis 缓存层

**新增文件**: `backend/app/core/cache.py`

```python
import hashlib
import json
from typing import Any
import redis.asyncio as redis
from app.core.config import settings

# Redis 连接池
redis_pool = redis.ConnectionPool.from_url(
    settings.redis_url or "redis://localhost:6379/0",
    max_connections=50,
    decode_responses=True,
)

async def get_redis() -> redis.Redis:
    return redis.Redis(connection_pool=redis_pool)

def cache_key(prefix: str, **kwargs) -> str:
    """生成缓存键"""
    raw = json.dumps(kwargs, sort_keys=True, ensure_ascii=False)
    hash_val = hashlib.md5(raw.encode()).hexdigest()[:12]
    return f"zhicetong:{prefix}:{hash_val}"

async def get_cached(prefix: str, **kwargs) -> Any | None:
    """获取缓存"""
    r = await get_redis()
    key = cache_key(prefix, **kwargs)
    data = await r.get(key)
    if data:
        return json.loads(data)
    return None

async def set_cached(prefix: str, value: Any, ttl: int = 600, **kwargs):
    """设置缓存"""
    r = await get_redis()
    key = cache_key(prefix, **kwargs)
    await r.setex(key, ttl, json.dumps(value, ensure_ascii=False))

async def invalidate_cached(prefix: str, **kwargs):
    """删除缓存"""
    r = await get_redis()
    key = cache_key(prefix, **kwargs)
    await r.delete(key)
```

### 4.5 向量检索优化

**文件**: `backend/app/services/rag/llama_index_adapter.py`

```python
from functools import lru_cache
from llama_index.core import VectorStoreIndex
from llama_index.vector_stores.postgres import PGVectorStore

# 缓存向量存储实例
@lru_cache(maxsize=1)
def get_vector_store() -> PGVectorStore:
    return PGVectorStore.from_params(
        host=settings.postgres_host,
        port=str(settings.postgres_port),
        database=settings.postgres_db,
        user=settings.postgres_user,
        password=settings.postgres_password,
        table_name=settings.llamaindex_vector_table,
        schema_name=settings.llamaindex_schema,
        embed_dim=settings.embedding_dimensions,
        use_jsonb=True,
        perform_setup=False,  # 生产环境关闭自动 setup
    )

# 缓存索引实例
@lru_cache(maxsize=1)
def get_index() -> VectorStoreIndex:
    return VectorStoreIndex.from_vector_store(
        vector_store=get_vector_store(),
        embed_model=get_embed_model(),
    )

def retrieve_nodes(
    query: str,
    filters: LlamaIndexFilter,
    top_k: int,
) -> list[NodeWithScore]:
    # 使用缓存的索引，避免每次重建
    index = get_index()
    retriever = index.as_retriever(
        similarity_top_k=top_k,
        filters=build_metadata_filters(filters),
    )
    return retriever.retrieve(query)
```

### 4.7 问答接口异步化

**文件**: `backend/app/api/routes/chat.py`

```python
from fastapi import APIRouter, Depends, HTTPException, status
from sqlalchemy.ext.asyncio import AsyncSession
from app.db.dependencies import get_async_db
from app.schemas.chat import ChatRequest, ChatResponse
from app.services.policy_qa_async import answer_policy_question_async

router = APIRouter(prefix="/chat", tags=["chat"])

@router.post("", response_model=ChatResponse)
async def chat(
    request: ChatRequest,
    db: AsyncSession = Depends(get_async_db),
) -> ChatResponse:
    try:
        return await answer_policy_question_async(
            db,
            question=request.question,
            session_id=request.session_id,
            user_id=request.user_id,
            top_k=request.top_k,
            policy_category=request.policy_category,
            include_expired=request.include_expired,
        )
    except RuntimeError as exc:
        raise HTTPException(
            status_code=status.HTTP_502_BAD_GATEWAY,
            detail=str(exc),
        ) from exc
```

## 5. 实施步骤

### 阶段一：基础优化（1-2周）

1. **数据库连接池**：修改 `session.py`，配置 pool_size=20
2. **向量检索缓存**：修改 `llama_index_adapter.py`，缓存索引实例
3. **Nginx 部署**：配置负载均衡和静态资源
4. **多 Worker 启动**：修改启动脚本，启用多进程

### 阶段二：缓存层（2-3周）

1. **部署 Redis**：Docker Compose 启动 Redis

### 阶段三：异步化（3-4周）

| PostgreSQL 主库 | 8C32G | 1台 | 200 连接 |
| PostgreSQL 从库 | 4C16G | 2台 | 只读查询 |

| Celery Worker | 4C8G | 2台 | LLM 任务队列 |
| Nginx | 2C4G | 1台 | 负载均衡 |

## 7. 风险与注意事项

1. **LLM API 限流**：第三方 API 可能有 QPS 限制，需要申请提升配额
2. **向量维度**：1024 维向量在大数据量下检索会变慢，考虑降维
3. **缓存一致性**：政策更新时需要清除相关缓存
4. **数据一致性**：主从复制有延迟，写后读可能不一致
5. **成本控制**：LLM 调用成本随并发增加，需要监控费用
